ACT 01 — THE ASK~150 words

The message

A recruiter found me on LinkedIn for a Lead DevOps/SRE role. The stack: EKS, Fargate, Aurora, Terraform/Terragrunt, Argo CD, GitHub Actions, Datadog. The ask underneath the tool list: can you build and run a reliability practice, not just click deploy.

I'd built pieces of this before, separately. I hadn't built the whole story in one place — something that actually breaks, and a real number for how fast I got it back. So instead of just replying with a resume, I decided to build the story first.

ACT 02 — THE BUILD~300 words

Standing it up

I started with the network, then the cluster, then the delivery pipeline — the same order a real platform team would, not the order that looks best in a demo.

Screenshot 2 of 13

`terragrunt run-all plan` output, full resource list, before anything exists. Caption idea: "before I touch AWS, here's the exact list of what's about to get created — no surprises."

One decision worth explaining up front: I ran this as a Fargate-only cluster — no EC2 node group at all. AWS runs every pod in its own micro-VM; I don't patch or size servers. The real tradeoff — no DaemonSets, so the observability agent later needs a different install path — is documented in ADR 001 rather than glossed over.

Screenshot 3 of 13

AWS Console → VPC → Resource Map. Two AZs, public/private split, one NAT per AZ.

The first real snag showed up exactly where I expected it to: CoreDNS came up Pending / Running — pick whichever actually happened until its namespace had a matching Fargate profile. A Fargate-only cluster has no fallback node to catch anything that isn't explicitly scheduled somewhere.

Screenshot 4 of 13

kubectl get pods -n kube-system — if CoreDNS was ever stuck Pending, that shot is worth more here than a clean success would be.

With the cluster up, Argo CD took over deployment — it watches the repo and reconciles the cluster to match, instead of me running kubectl apply by hand.

CLOSING~80 words

Back to the recruiter

The reply I'd send isn't "I know these tools." It's: here's a service I deployed with GitOps, a database I killed on purpose, and the real number for how fast I got it back — plus what it cost and that I cleaned up after myself. That's the version of "Lead SRE" this role is actually asking about, and it's easier to defend in an interview than any bullet point would be.
